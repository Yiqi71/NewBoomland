## 二、对照 PRD 缺失的内容（missing）

### M1. 赛季详情页「关键数字」没有随阶段变化（SDP-001）✅ 已修复 2026-11-12
> 处理：`guestStats` 按阶段输出——即将开始：参赛人数/命题数/奖励池/积分池总量；进行中：+今日评分（按推演时点的北京时间自然日）/R5 项目数/积分池使用率（已分配/总量；已用/已分配）；结算中起改评分总次数；定格/归档：评分总次数+积分池已用。不计分活动隐藏评分与积分口径。测试已同步。
`guestStats` 固定显示 参赛人数 / 参赛项目 / 公开作品 / 奖励池。按 SDP-001 应为：
- 即将开始：已通过选手、**命题数**、奖励池、**积分池总量** →（后两者缺，且开赛前显示 0 项目/0 作品意义不大）
- 进行中：另加 **今日评分、R5 项目数、积分池使用率** → 全缺。注意 `guestEventMetrics` 已算出 `r5 / allocationRate / usageRate`，只是没展示
- 结算中：今日评分改为 **评分总次数** → 缺
- 已定格/归档：**评分总次数、R5 项目数、积分池已用** → 缺

### M2. 定格后的结算摘要不完整（SDP-001、A.6-4）✅ 已修复 2026-11-12
`guestFinalSummary` 只有 已核定 / 已发放 / 发放进度。缺：**奖励池、积分池已用、未分配处理**（`unallocatedDisposition` 字段已有，未渲染）。
> 处理：结算摘要增加 奖励池 与 未分配处理（unallocatedDisposition）；积分池已用 放在定格阶段的关键数字行（见 M1），避免重复。

### M3. 火热赛季页缺「随所选赛季切换的内容区块」（9.6、ARC-001）🚫 不做（2026-11-13 用户决定：在列表页嵌详情反直觉，维持卡片点进详情的结构）
PRD 要求轮播切换后，下方的 公告 / 命题 / 本季规则 / 奖励池 / 前 5 名（完整排行榜入口）/ 最近动态 同步更新。现在的火热赛季页只有 hero + 卡片网格，必须点进详情页才能看到这些。`guestHomeContent()` 就是为此准备的，接上即可。另外卡片本身缺 报名状态、R5 项目数、积分池使用率；「并行 N 个」计数也未显示。

### M4. 不计分赛季没有闭环（SEA-006）
展示端已支持（`guestScoringEnabled`、`rules({hideScoring})`、票面「不计分活动」），但：
- 赛季配置里**没有「不计分」开关**，主办方无法真正创建不计分赛季（演示数据也没有靠 `noScoring` 字段的例子）；
- `publishChecks()` 对不计分赛季**没有豁免**预算>0、积分池>0、评委已分配三项门槛——按 PRD 这三项应免除。

### M5. 已批准后改关键参数不需要重新批准（0.3 决策 5、待定 5、5.7）
- `season-config` 修改 兑换比例（仅开赛后锁定）、单次上限、复核阈值、命题上限 保存即生效，只发公告 + 记规则版本；PRD 要求**已批准赛季改这些须重新平台批准**（改赛程/公告/可选条目才不需要）。
- `add-pool` 追加积分池同样无需重新批准，且**没有生成新版本记录**（5.7：追加积分池生成新版本）、没有公告。

### M6. 组队截止没有任何硬校验（5.0、5.3、12.7、9.9）
- `canWrite('project')` 只看阶段与报名状态，**组队截止（dates[3]）过后仍可创建项目**；
- 9.9 要求的「组队已截止」主按钮状态不存在；
- **项目命题/成员变更功能完全没有**（组队截止前发起人自助增删替换命题、截止后主办方审批、有作品标注的命题不能移除返回 409——5.3 第 6 条、A.7-8）。

### M7. 命题冻结按「阶段」而非按「冻结日」（5.0、12.7）
`challengeFrozen()` = `phase!=='upcoming'`，即开赛瞬间就冻结，早于配置的 `challenge_freeze_at`（dates[4]，可晚至组队截止）。开赛后、冻结日前本应还能新增/下线命题。原型无真实时钟，可改用 `seasonTimelineNow()` 的推演时点与 dates[4] 比较。

### M8. 赛程校验缺口（5.0）
`season-config` 没有校验 **报名截止 < 开赛**（dates[1] 与 dates[2] 无任何约束）；另外六个关键点要求「严格递增」，当前校验允许 组队截止=作品截止、评分截止=结算日 等相等情形。

### M9. 待批准赛季的预览页缺「批准 / 驳回」（9.9）
管理员预览待批准赛季时，页面顶部应显示「批准」「驳回」按钮和「待平台批准·未公开」提示；现在批准入口只在平台后台列表页。

### M10. 已撤回后无法重新报名（9.9）
撤回后 `state.application` 仍存在，apply 页直接提示「已经提交过本季报名」，9.9 要求已撤回显示「重新报名」。（退出赛季/候补递补确认等属待定 14/15，原型已在弹窗声明待确认，算有意留白。）

### M11. 微信群状态只在部分阶段显示（9.9）
`participantSummary` 仅 `['upcoming','active']` 显示微信群徽标；PRD 要求已通过的选手**所有阶段**都显示（待邀请/已邀请/已加入）。

### M12. 大厅与「SN 黑客松」专区缺失（7.12、ARC-005、6.1）
顶部导航「大厅」是禁用的死链接，`home` 路由直接复用火热赛季页。缺：当前置顶赛季+倒计时+积分池使用率、并行赛季入口、Top10、SN 黑客松专区（进行中城市站/往届/产出项目/「全部 SN 黑客松」入口）。往季档案里也没有任何 `imported` 历史黑客松示例数据（ARC-006）。

### M13. 9.9 主按钮文案细节未按身份×阶段细化
- 评委：即将开始应为「查看我的评委授权」、进行中「去评委台（分配余额 N）」、评分截止后「评分已截止」→ 现统一「进入评委台」；
- 主办方：「主办方后台·待审核 N」「等待平台批准」→ 现统一「进入主办方后台」；
- 企业：已定格应为「命题报告」→ 现统一「查看本企业命题」。
- 另：SDP-002 主按钮优先级是 主办方＞本人有项目＞评委＞企业＞报名，代码顺序为 organizer>admin>judge>enterprise>报名（单身份原型下影响小，留档备查）。

### M14. 治理类小缺口
- SEA-001：黑客松必须填城市——无校验（city 默认「线上」也能发布黑客松）；
- SEA-003：缩短已公布截止时间「必须在公告中说明影响」——现为通用文案「主办方更新了本季配置」；
- SEA-005：可选规则条目**不得与平台规则冲突**（如「完成里程碑获得积分」「阶段评审+最终评审」）——无任何校验，可直接录入冲突条目。

### M15. 带入长期项目只有表单选项（LIB-003）
「带入本人已有项目」只是一个 select 值，没有可选的既有项目列表；也没有「同一项目同一时间只能参加一个未结束赛季」的校验。

### M16. 其他展示缺口
- 赛季详情页「入口」行缺 **往季档案** 入口（命题库、关注已有）；
