## 一、多余的东西（不该出现在页面上的）

### A1.（高）DEMO 演示赛季跑到了公开页面上 —— ✅ 已修复（2026-11-13）
> 修复方式：`guestRecordCatalog()` 过滤带 `isDemoSeason` 标记的记录；`buildParticipantDemo()` 生成演示记录时保留该标记；tests/validate.py 新增回归测试。156/156 测试通过。
- `ensureDemoSeasons()` 不管什么身份（包括访客）都会创建 9 个 DEMO 赛季，其中 7 个还是"已批准"状态。
- 公开页面的目录 `guestRecordCatalog()` 会把它们全算进去，造成两个问题：
  - **往季档案**里多出"夏日共创季""春日探索季"，内容和 S01 一模一样（同样的项目、作品、主办方），档案数量也变大了；
  - **命题库**里同样的 3 条命题重复出现了大概 6 次（这些 DEMO 季没有自己的命题，代码回落到了全局命题列表），赛季筛选下拉也全是 DEMO 季。
- 这些季本来只是给主办方后台"全部赛季"看状态用的，不该让访客看到。
- **怎么修**：`guestRecordCatalog()` 里过滤掉 `isDemoSeason`，或者把 DEMO 季改成未批准。

### A2.（高）用"报名中"代替了赛季状态 —— ✅ 已修复（2026-11-13）
> 修复方式：`activityDisplayStatus()` 恢复为只返回赛季状态；新增 `registrationDisplayLabel()` 单独产出报名状态（即将开始阶段显示 未开放/报名中/已截止，报名窗口落在进行中时显示"报名中"，其余阶段不显示）。票卡、列表页大图、详情页头图、工作台 chips 均改为两枚标签并列（报名标签在赛季状态右边）。更新 2 条旧断言 + 新增 1 条回归测试，157/157 通过。
- `activityDisplayStatus()` 在"即将开始 + 报名开放"时直接返回"报名中"，并且这是页面上**唯一**的状态标签，用在了：火热赛季票卡、列表页大图、详情页头图、参赛者工作台的赛季标签。
- PRD 5.0 明确说了：**不能用"报名中"代替赛季状态**，两个状态要分开显示（比如"即将开始 · 报名中"）。
- 票卡代码里其实算好了报名状态（`registrationStatus`），只是没显示出来。

### A3.（中）赛季详情页有两套实现 —— ✅ 已修复（2026-11-13）
> 修复方式：删除旧版 `currentSeasonPage/currentSeasonStats/currentSeasonResults/seasonDetailHeader/seasonDetailSupplements`，全部走 `guestSeasonPage`；草稿/待批准赛季对管理者显示顶部横幅「草稿/待平台批准 · 未公开」，管理员在横幅上直接「批准发布/驳回」（顺带满足 9.9 的管理员预览要求）。改写 2 条旧断言 + 新增 1 条回归测试。
- 主办方预览草稿时走的是旧版 `currentSeasonPage()`，访客走的是新版 `guestSeasonPage()`，两套各写了一遍公告、规则、命题、统计。
- 旧版的统计数字（"已评积分""本季奖励池"）和 PRD SDP-001 规定的关键数字不是一个口径，以后改一处漏一处。
- **建议**：只留新版，管理预览时在顶部加一条"待平台批准·未公开"+ 批准/驳回按钮就行。

### A4.（中）产品共生的项目卡上显示"赛季贡献积分" —— ✅ 已修复（2026-11-13）
> 修复方式：`projectCard` 增加 `score` 开关，产品共生（长期项目库）不再显示积分；命题页等赛季语境保持不变。新增 1 条回归测试。目前测试共 159/159 通过。
- PRD 9.7 里长期项目卡的字段没有积分这一项；而且积分是按赛季单独记账的，放在长期项目库上说不清是哪一季的。应该去掉。

### A5.(中)没设名额时还显示"/ 不限"
- 票卡、详情页统计都会显示"已通过 N / 不限"。
- PRD 的口径（待定 14、附录 A.1-2）是：**没设名额就不显示分母**。"不限"这几个字是多余的。

### A6.（低）列表页大图写死了"核心团队 1—3 人" —— ✅ 已修复（2026-11-13）
> 修复方式：改为读所选赛季的 `teamLimit`（`核心团队 1—${featured.record.season.teamLimit||3} 人`），与详情页同一口径；新增 1 条回归测试。目前测试共 160/160 通过。
- 不读赛季配置的 `teamLimit`，切到别的赛季也显示同一句，可能是错的。详情页是读配置的，列表页也应该读。

### A7.（低）排行榜页的"商业成果"混进了 R2 和自述成果 —— ✅ 已修复（2026-11-13）
> 修复方式：`rankingsResultsSection()` 改为复用详情页的 `guestOutcomes()`（只取已核验的 R3–R6，每项目取最高等级），删除 R2 与"自述成果"分支，两页口径一致。新增 1 条回归测试，161/161 通过。
- 详情页的战果只显示**已核验的 R3–R6**（这是对的），但排行榜页把 R2 和没核验的"自述成果"也放进来了，两边口径不一样。

### A8.（低）顶栏多了一个"我的赛季"按钮
- PRD 6.0 顶栏右边只有：搜索、公告红点、"提交产品"、"我的"菜单。这个独立按钮是额外加的，不算大问题，但和文档不符。

### A9.（低）没用的代码
- views.js 里的 `workspacePage()` 和 `rewardsPage()` 被 participant.js 覆盖了，是死代码；
- `guestHomeContent()` 写好了但从没被用过（见下面 B1）；
- 评分的每日额度写死了 300，PRD 说应该按赛季配置。

## 二、缺的东西（PRD 要求、网站没有）

### B1.（高）火热赛季页缺下半部分（9.6 / ARC-001）
- PRD 要求：切换轮播后，下方要跟着显示所选赛季的 **公告 / 命题 / 规则 / 奖励池 / 前 5 名 / 最近动态**。
- 现在列表页只有大图 + 卡片网格。其实 `guestHomeContent()` 已经写好了，只差接上（代码里也留了 TODO）。
- 票卡上也缺：赛程时间轴、R5 项目数、积分池使用率，以及单独的报名状态标签（见 A2）。

### B2.（高）"不计分赛季"做不了（SEA-006） —— ✅ 已修复（2026-11-13）
> 修复方式：赛季发起页与赛季配置页各加「不计分活动」勾选（写入 `season.scoringEnabled=false`，展示端现成逻辑直接生效）；发布检查对不计分赛季免除 预算/积分池/评委 三项门槛并显示豁免说明；黑客松不允许设为不计分；计分方式纳入规则版本留痕。新增 2 条回归测试。
- 显示那边的判断都写好了（不计分就隐藏积分、奖金、排行榜），但**没有任何地方能把一个赛季设成不计分**：配置页没有开关。
- 而且发布检查固定要求 预算>0、积分池>0、有评委——PRD 说不计分赛季这三项要免掉。
- 所以这条路现在整个走不通。

### B3.（高）主办方只能填一个（SEA-001 / 9.10） —— ✅ 已修复（2026-11-13）
> 修复方式：赛季配置页改为多选勾选（选项来自组织列表）；新数据存 `season.organizerOrgs` 数组，旧记录的 organizer 字符串读取时自动拆分回落，不迁移、不影响已创建记录；票卡/大图/详情页/档案卡统一用 `seasonOrganizerLabel()` 显示；往季档案按单个组织筛选；发布门槛按组织数组判断。组织的新增/重命名/删除放在管理员"主办方组织与成员"页（可见按钮，不用右键；在用组织不可删，改名/删除均不回写历史记录）；主办方端只能勾选，提示组织由平台管理员维护（待定 8）。新增 2 条回归测试，165/165 通过。
- 现在 `organizer` 就是一个文本框（demo 里用 "Proto Seeds × SheNicest" 一个字符串凑合）。
- PRD 要求一个赛季可以有**多个主办方组织**，各自有权限。往季档案按主办方筛选也会因此不准。

### B4.（中）主按钮没有按"身份 × 阶段"变化（9.9）
现在评委、企业、主办方不管什么阶段都是同一个按钮。按 PRD 应该是：
- 评委：即将开始→"查看我的评委授权"；进行中→"去评委台（余额 N）"；评分截止后→"评分已截止"；结算中→"我的评分记录"；
- 企业：已定格→"命题报告"；
- 主办方：待批准→"等待平台批准"；报名中→"主办方后台·待审核 N"；
- 报名未通过→"查看原因"；已撤回→"重新报名"；候补在组队截止后→"候补已结束"；
- 管理员在待批准赛季的预览页顶部应该直接有"批准/驳回"按钮（现在只在治理列表里有）；
- 已通过选手的微信群状态应该**每个阶段都显示**（现在只有开赛前后显示）。

### B5.（中）候补递补和退赛没做（待定 14 / 15 已有结论）
- 候补只有一个标签，没有"组队截止前按顺序递补、48 小时内确认"的流程；
- 只能在审核前撤回报名，没有"组队截止前退出赛季"（退出不删作品和积分）。弹窗里还写着"细则待确认"，但 V2.6 已经定了。

### B6.（中）往季档案里一场黑客松都没有（ARC-002 / ARC-006）
- 档案筛选选"黑客松"永远是空的（H02 还在进行中，进不了档案）。PRD 要求历史黑客松要进往季档案。至少该补一条演示数据。

### B7.（中）搜索搜不到赛季（FOL-002）
- 现在只能搜项目和命题。PRD 要求能搜：项目、人、命题、**赛季**。

### B8.（中）大厅页没有（6.1 / 7.12 / ARC-005）
- "大厅"现在直接跳火热赛季页，导航按钮也是灰的。缺：置顶赛季 + 实时战果、SN 黑客松专区、倒计时、积分池使用率等。如果是故意先不做，建议在 docs 里写明。

### B9.（低）规则卡的可选条目编辑太简单（SEA-005 / 9.10）
- 现在是一个大文本框一行一条。PRD 要求能逐条 新增 / 排序 / 隐藏 / 预览。（必要条目锁定、改规则留版本发公告这些已经是对的。）

### B10.（低）零碎小项
- 命题库入口没有数量角标和高亮（9.6 写的是"命题库 · N"；现在只有往季档案有角标）；
- 详情页缺"往季档案"直达入口；
- 黑客松没有强制填城市的校验；
- 异议没有限制"进入结算后 7 天内"的窗口（现在随时能提）；
- "我的"菜单里缺"我的奖励"入口；
- "没有进行中赛季时导航显示为『赛季』"没做（演示环境永远有赛季，影响很小）。

## 三、建议的处理顺序

1. **A1** DEMO 季泄漏——公开页数据被污染，加一个过滤就能修；
2. **A2** 赛季状态和报名状态分开显示——全站统一口径；
3. **B1** 火热赛季页接上下半区——代码现成，接线即可（记得同步改 tests/validate.py 的断言）;
4. **B2** 不计分配置、**B3** 多主办方——涉及数据结构，早改早好；
5. 其余按演示需要逐项补。

## 四、这次确认过没问题的（不用改）

赛季状态机和旁路状态、9 项发布门槛、赛程顺序校验、规则卡必要条目由配置生成 + 版本留痕 + 自动公告、唯一置顶、复制上季不带预算/积分池/评委/命题/报名、暂停/取消/结算/定格的流转和文案、评委公示（不公示额度和联系方式）、赛后结果列表的字段（包括公开互动热度，这是 7.12 要求的）、时间轴包含命题冻结/作品截止/评分截止和"今天"标记、北京时间标注、公告红点和必发公告的事件。
